# 資產總覽的資金移轉歷史入口研究

本筆記依現有 Kinfolio 程式碼研究；僅提出方案，不修改產品介面。

## 推薦方案

在個別持有人「投資帳戶」區塊標題右側，於「新增帳戶」旁新增 **移轉記錄** 按鈕，使用歷史／雙向箭頭圖示搭配文字。點選後開啟唯讀歷史彈窗，不離開目前持有人與檢視日期。投資帳戶區塊是移轉對象的所在位置，與既有「新增帳戶」入口並列可形成清楚脈絡；此為設計建議，現有區塊見 [public/app.js:407](../../public/app.js#L407)。

全部持有人總覽沒有投資帳戶表格，因此還需在頁面上方提供同名入口；否則刪除側欄後，會失去檢視全部移轉與跨持有人新增移轉的入口。現有全部持有人總覽由 `holdersOverview()` 呈現，頁首目前只有新增持有人；個別持有人頁首則已有新增資金移轉入口。見 [public/app.js:275](../../public/app.js#L275)、[public/app.js:443](../../public/app.js#L443)。

彈窗標題建議為「移轉記錄」，副標顯示「全部持有人／持有人名稱 · 截至 YYYY-MM-DD」，列出筆數與記錄。右上角保留關閉，另提供「新增移轉」按鈕；新增時沿用現有表單，儲存後回到歷史並更新資料。這需要新增少量返回狀態，因為目前 `openForm()` 會替換共用 modal 內容，儲存後直接關閉。見 [public/app.js:598](../../public/app.js#L598)。

## 行為規則

- **篩選**：沿用目前持有人與 `asOf` 日期，只顯示截至檢視日的歷史；全部持有人顯示全部。現有 `transferPage()` 已實作此規則。[public/app.js:482](../../public/app.js#L482)
- **跨持有人歷史**：轉出或轉入任一端屬於目前持有人即可顯示。每筆移轉以 `transfer_out` 為主，配對 `transfer_in`，因此即使兩端都屬於同一持有人也只顯示一列。[public/app.js:486](../../public/app.js#L486)
- **順序及欄位**：日期由新到舊，同日按事件 ID 倒序；保留日期、轉出／轉入帳戶及持有人、兩端原幣金額／本金、備註。不要把跨幣別兩端金額直接相減或合計。[public/app.js:497](../../public/app.js#L497)
- **新增範圍不變**：個別持有人新增表單目前只列自己帳戶，且需至少兩個帳戶；全部持有人新增表單可選全部帳戶，包括跨持有人。此次不順便擴大個別持有人表單範圍。[public/app.js:737](../../public/app.js#L737)
- **空狀態**：沒有記錄仍能開啟，顯示「截至此日期尚無移轉記錄」；不足兩個可移轉帳戶則給清楚原因，不隱藏歷史入口。這可避免僅有單一帳戶的持有人無法查看從其他持有人轉入的歷史。
- **唯讀歷史**：不新增直接刪除移轉功能；後端目前禁止直接刪除 `transfer_in`／`transfer_out` 事件，應維持一致。[src/worker.js:365](../../src/worker.js#L365)
- **字級**：沿用最近統一的 13px 資訊字級，彈窗需單獨套用樣式，因為目前統一規則只涵蓋 `.workspace` 後代。[public/style.css:1566](../../public/style.css#L1566)

## 實作建議

1. 將 `transferPage()` 拆成不依賴頁面外框的查詢／表格呈現函式，供共用 modal 使用；不新增 API、不搬動或重寫交易資料。現有 state 已含 events 與 transfers。[src/worker.js:109](../../src/worker.js#L109)
2. 加入 `openTransferHistory()` 與獨立的 `data-transfer-history` 動作。歷史視窗使用較寬的 dialog，桌面橫向表格、手機保留橫向捲動；保留標準 dialog 的 Escape、關閉及背景點擊行為。現有 modal 及背景點擊邏輯見 [public/app.js:1183](../../public/app.js#L1183)，寬度樣式見 [public/style.css:1152](../../public/style.css#L1152)。
3. 共用 modal 中的歷史／表單切換要明確清除樣式與資料標記，避免殘留 `detailAccount` 或 `transfer-dialog`；保存開啟按鈕並在關閉後還原焦點。現有重置點見 [public/app.js:598](../../public/app.js#L598)。
4. 完成全部與個別持有人入口後，才移除 sidebar 的 transfers label、頁面分支及相關頁首分支。相關集中於 [public/app.js:258](../../public/app.js#L258)。
5. 若採用「新增後回到歷史」，取消新增也應回歷史；若從頁首原有資金移轉直接開表單，維持原本儲存後關閉的行為。用明確來源狀態區分，避免改變其他流程。

## 驗證重點

- 個別持有人與全部持有人皆能開啟；側欄不再出現資金移轉。
- 本人內部移轉只出現一列；跨持有人兩端均可查到；無關持有人看不到。
- 檢視日期排除較新的記錄，同日排序正確；空記錄仍可開啟。
- 單帳戶可查看跨持有人移入歷史，但個別持有人新增仍遵守兩帳戶限制。
- 新增保持現有 API 權限、重送保護、原子性與本金計算，不改交易資料語意；現有後端移轉入口見 [src/worker.js:231](../../src/worker.js#L231)。
- 開啟／取消／新增成功／失敗／Escape／背景點擊／焦點還原，以及 13px 字級、窄螢幕表格捲動。

## 決策結論

推薦「**投資帳戶標題旁的移轉記錄按鈕＋唯讀彈窗**」，並在全部持有人總覽頁首保留對應入口與新增能力。比只放無文字小圖示更容易辨識，也能避免把完整歷史直接塞進已經較長的資產總覽。此結論屬於根據現有介面與程式結構提出的設計建議。
