# 現金支出規劃：Kinfolio 架構研究

研究日期：2026-10-27。範圍為本機原始碼與結構；未改動功能、未讀取密鑰、未連線正式資料庫。此文件的產品方案為建議，現況敘述附有程式來源。本目錄與祖先目錄未發現適用的 AGENTS.md。

## 範圍更新

依使用者補充，規劃固定使用台幣，不提供幣別選擇，與既有資產資料獨立。銀行帳戶連結、精確入扣款日期與外幣支付能力不列入開發階段。月度模型與資料結構以 [功能提案](../cash-planning-proposal.md) 為準。

## 結論

適合新增獨立「現金規劃」模組，沿用持有人與登入隔離，將目前可用現金、未來收入／支出規則、預測結果分開。不要把未來支出寫成現有 events：它是實際投資本金／估值帳本，且預設拒絕未來日期。現有 goals 只有資產／淨資產里程碑，也不能表達支付時間與現金缺口。[來源：../../public/domain.js:56、../../src/worker.js:184、../../src/worker.js:322、../../migrations/0001_initial.sql]

## 現有資料與計算

| 領域 | 已存在 | 與新功能的關係 |
| --- | --- | --- |
| 身分與歸屬 | users → holders → accounts／loans／goals；登入者資料以 user_id 隔離 | 計畫應有 user_id 與 holder_id，所有外鍵／查詢沿用雙重歸屬檢查 |
| 投資帳戶 | 類型僅股票、期貨、美股、未上市公司；幣別 TWD／USD／JPY | 沒有銀行存款／純現金帳戶，不能直接從「總資產」取得可支付現金 |
| 帳本 | events 表示 opening、valuation、deposit、withdrawal、transfer_in／out | 投入不等於薪資、提領不等於生活支出，不能直接推斷收支分類 |
| 金額 | 最小貨幣單位整數；FX 是每原幣對台幣的百萬分之一；BigInt 中間運算 | 僅重用金額整數與安全範圍驗證，不使用匯兌規則 |
| 現金持股模式 | portfolios.cash 存券商帳戶的現金；僅台幣股票／美元美股可啟用 | 本功能不連結或讀取券商現金，期初現金獨立手填 |
| 貸款 | 剩餘本金快照，建立時 annual_rate 寫 0 | 沒有期付金／繳款日／攤還表；房貸月付要另外輸入，不從本金推估 |
| 目標 | TWD target、date、basis=assets/net，按持有人歸屬 | 目標不是待支付義務，不能自動扣現金 |

## 可重用的整合點

- **資料 API 與備份**：`data()` 逐表以 user_id 篩選，`/api/state` 回傳全狀態；`/api/export` 使用同一資料函式並回傳 schemaVersion 2。增加規劃表後須加入兩者，必要時升備份版本。現有無備份匯入。[來源：../../src/worker.js:29、../../src/worker.js:104、../../README.md]
- **寫入一致性**：所有一般修改透過 `mutate()` 以 revisions／mutations 觸發器做樂觀鎖與 D1 batch；前端 api() 自帶目前 version。計畫 CRUD 應沿用它，避免不同分頁覆寫設定。[來源：../../src/worker.js:59、../../public/app.js:166、../../migrations/0001_initial.sql:3]
- **前端分頁**：原生 ES modules，`render()` 內 labels、導覽、描述、按鈕、頁面映射皆需新增項目。目前 app.js 集中 UI，建議將新計算與頁面各放獨立模組。[來源：../../public/app.js:251、../../README.md]
- **篩選語意**：共用檢視日期只能到今天，代表歷史實績。新頁應有明確的「計畫起日／預測到」，不要拿全域 asOf 當未來終日；現有全部持有人總覽逐人呈現而不合計跨人財務，新頁預設也應逐人計畫，跨人共用資金需明確選擇。[來源：../../public/app.js:271、../../public/app.js:433、../../README.md]
- **資料新鮮度**：目前持股與現金只有最新設定，歷史持股組成保存在已儲存快照。若支援歷史起日，不可直接套用今天的 portfolios.cash，應保存獨立的期初資金快照或只允許目前起算。[來源：../../migrations/0003_portfolios.sql、../../src/portfolios.js:24、../../src/portfolios.js:289]

## 建議首版模型與計算界線

以下是新增設計，尚未實作。

1. `cash_plans` 保存 user_id、holder_id、計畫名稱、起訖月份、安全底線與取整單位，不提供幣別選擇。
2. `cash_plan_items` 保存項目名稱、分類與收入／支出方向；`cash_plan_months` 保存每項每月金額與確認狀態。
3. `cash_balance_snapshots` 保存手填現金基準月份與金額，不引用既有帳戶。
4. 共用純計算模組負責逐月現金餘額、保留額與缺口；獨立 API 與 UI 負責驗證、儲存和顯示。

計算採期初現金加逐月累計淨收支，比對安全底線，顯示首次不足月份。只做月底估算，沒有逐日收支排序或入扣款日期。預測不更動既有資產、貸款或交易資料。

## 重要風險與驗證

| 風險 | 必須明確處理 |
| --- | --- |
| 現金與總資產混用 | 缺少現金來源時顯示未設定，不以資產估值替代；來源重複時不可相加兩次 |
| 預計與實際重複 | 期初快照的截止日、當日項目是否包含、實付後是否仍預測都要固定 |
| 月份邊界 | 驗證年月、跨年、期間起訖與單月覆寫，不展開逐日週期 |
| 持有人 | 同一登入者的兩位持有人也不應默認能互用現金；登入者間不得共享 |
| 負餘額 | 投資帳本拒絕負值，但預測必須允許負數才能呈現缺口；不要重用 validateTimeline 限制 |
| 未來月份 | 使用獨立年月驗證，不沿用實際投資帳本禁止未來日期的限制 |
| 欠缺輸入 | 空白收入／支出／現金不應無聲當零；要區分未設定與已確認為零 |

現有單元測試涵蓋精確匯兌、補登、同日排序、日期校驗；整合測試使用獨立 Worker 與隔離 D1，已有兩個登入者的隔離、版本衝突、移轉與備份測試，可延伸。新模組至少測：期中缺口但期末盈餘、恰好等於保留額、無收入、零現金、大額精度、跨年與月份邊界、停用項目、重複來源、跨持有人及跨登入者拒絕、並行修改衝突、備份包含完整規劃設定。[來源：../../tests/domain.test.js:92、../../tests/domain.test.js:124、../../tests/domain.test.js:136、../../tests/domain.test.js:142、../../tests/integration.mjs:1、../../tests/integration.mjs:352]
